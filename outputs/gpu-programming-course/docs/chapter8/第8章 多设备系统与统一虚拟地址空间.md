# 第8章 多设备系统与统一虚拟地址空间

## 8.1 引言

到目前为止，我们的讨论都集中在单个 GPU 设备上。然而，在实际的服务器和工作站环境中，一个主机系统常常配备多块 GPU——从深度学习训练节点的 8 卡配置到小型工作站的 2 卡配置。如何有效地管理和利用多设备系统，是 CUDA 程序员必须掌握的进阶技能。

本章将深入介绍多设备系统的编程模型，涵盖设备枚举与选择、跨设备流与事件行为、P2P（Peer-to-Peer）内存访问与拷贝、统一虚拟地址空间（UVA）、进程间通信（IPC），以及错误检查的最佳实践。掌握这些内容后，你将能够编写充分挖掘多 GPU 系统潜力的程序。

## 8.2 设备枚举与属性查询

### 8.2.1 枚举可用设备

一个主机系统可能有多个 CUDA 设备。在使用任何设备之前，我们首先需要知道系统中有多少个设备可用。以下代码展示了如何枚举这些设备、查询它们的属性，并确定 CUDA 启用设备的数量：

```cuda
int deviceCount;
cudaGetDeviceCount(&deviceCount);
int device;
for (device = 0; device < deviceCount; ++device) {
    cudaDeviceProp deviceProp;
    cudaGetDeviceProperties(&deviceProp, device);
    printf("Device %d has compute capability %d.%d.\n",
           device, deviceProp.major, deviceProp.minor);
}
```

`cudaGetDeviceCount()` 返回系统中可用的 CUDA 设备数量。`cudaGetDeviceProperties()` 则填充一个 `cudaDeviceProp` 结构体，其中包含了设备的详细属性信息。

### 8.2.2 关键设备属性

`cudaDeviceProp` 结构体中包含许多有用的属性，以下是最常用的几个：

| 属性 | 类型 | 描述 |
|------|------|------|
| `name` | char[256] | 设备的 ASCII 标识字符串（如 "Tesla V100-PCIE-32GB"） |
| `major`, `minor` | int | 计算能力主版本号和次版本号 |
| `totalGlobalMem` | size_t | 全局内存总量（字节） |
| `sharedMemPerBlock` | size_t | 每个线程块的共享内存最大量（字节） |
| `regsPerBlock` | int | 每个线程块的 32 位寄存器最大数量 |
| `warpSize` | int | 线程束大小（warp size），始终为 32 |
| `maxThreadsPerBlock` | int | 每个线程块的最大线程数 |
| `maxThreadsDim` | int[3] | 每个维度上的最大线程数 |
| `maxGridSize` | int[3] | 每个维度上的最大网格大小 |
| `clockRate` | int | GPU 时钟频率（kHz） |
| `multiProcessorCount` | int | 多处理器（SM）数量 |
| `concurrentKernels` | int | 设备是否支持并发核函数执行（1=是） |
| `asyncEngineCount` | int | 异步拷贝引擎数量（决定了并发数据传输的能力） |
| `unifiedAddressing` | int | 设备是否使用统一地址空间（1=是） |
| `canMapHostMemory` | int | 设备是否支持映射页锁定主机内存（1=是） |
| `deviceOverlap` | int | 设备是否可以同时执行拷贝和核函数（1=是） |

### 8.2.3 完整设备属性查询示例

以下是一个更完整的设备信息查询程序，推荐你在自己的系统上运行它以了解你所拥有的 GPU：

```cuda
#include <stdio.h>
#include <cuda_runtime.h>

int main() {
    int deviceCount;
    cudaGetDeviceCount(&deviceCount);

    printf("Found %d CUDA device(s)\n\n", deviceCount);

    for (int i = 0; i < deviceCount; i++) {
        cudaDeviceProp prop;
        cudaGetDeviceProperties(&prop, i);

        printf("=== Device %d: %s ===\n", i, prop.name);
        printf("  Compute Capability:        %d.%d\n", prop.major, prop.minor);
        printf("  Multiprocessors (SM):      %d\n", prop.multiProcessorCount);
        printf("  GPU Clock Rate:            %.2f GHz\n",
               prop.clockRate * 1e-6f);
        printf("  Global Memory:             %.2f GB\n",
               prop.totalGlobalMem / (1024.0 * 1024.0 * 1024.0));
        printf("  Shared Memory per Block:   %zu KB\n",
               prop.sharedMemPerBlock / 1024);
        printf("  Registers per Block:       %d\n", prop.regsPerBlock);
        printf("  Max Threads per Block:     %d\n", prop.maxThreadsPerBlock);
        printf("  Warp Size:                 %d\n", prop.warpSize);
        printf("  Concurrent Kernels:        %s\n",
               prop.concurrentKernels ? "Yes" : "No");
        printf("  Async Engine Count:        %d\n", prop.asyncEngineCount);
        printf("  Unified Addressing:        %s\n",
               prop.unifiedAddressing ? "Yes" : "No");
        printf("  Can Map Host Memory:       %s\n",
               prop.canMapHostMemory ? "Yes" : "No");
        printf("\n");
    }

    return 0;
}
```

```bash

./device_query
```

## 8.3 设备选择

### 8.3.1 使用 cudaSetDevice 切换设备

主机线程可以随时通过调用 `cudaSetDevice()` 来设置它操作的设备。设备内存分配和核函数启动都发生在当前设置的设备上；流和事件也会关联到当前设置的设备。如果从未调用 `cudaSetDevice()`，当前设备默认为设备 0。

以下代码示例说明了设置当前设备如何影响内存分配和核函数执行：

```cuda
size_t size = 1024 * sizeof(float);
cudaSetDevice(0);            // 设置设备 0 为当前设备
float* p0;
cudaMalloc(&p0, size);       // 在设备 0 上分配内存
MyKernel<<<1000, 128>>>(p0); // 在设备 0 上启动核函数
cudaSetDevice(1);            // 设置设备 1 为当前设备
float* p1;
cudaMalloc(&p1, size);       // 在设备 1 上分配内存
MyKernel<<<1000, 128>>>(p1); // 在设备 1 上启动核函数
```

这表明在 `cudaSetDevice(0)` 后调用的 `cudaMalloc` 和核函数启动都在设备 0 上执行，而切换到设备 1 后，后续操作在设备 1 上执行。这是一个关键概念：<strong>每个主机线程在同一时刻只有一个"当前设备"</strong>，所有与设备相关的 CUDA 运行时调用都在该设备上生效。

### 8.3.2 多线程与设备亲和性

在多线程程序中，每个线程可以独立地设置自己的当前设备。这在需要多个线程同时驱动多个 GPU 时特别有用。需要注意的是，CUDA 上下文是与 CPU 线程相关联的——每个主机线程在使用特定设备时会创建自己的 CUDA 上下文。

```cuda
// 线程函数示例：每个线程驱动一个不同的 GPU
void* gpuThread(void* arg) {
    int deviceId = *(int*)arg;
    cudaSetDevice(deviceId);
    // 此后所有 CUDA 调用都在 deviceId 上执行
    // ...
    return NULL;
}
```

## 8.4 多设备环境下的流与事件行为

流和事件在多设备环境中的行为需要仔细理解：

- <strong>核函数启动</strong>如果发到不与当前设备关联的流中，将会失败。每个流都与创建时所在的设备绑定了。

```cuda
cudaSetDevice(0);               // 设置设备 0 为当前设备
cudaStream_t s0;
cudaStreamCreate(&s0);          // 在设备 0 上创建流 s0
MyKernel<<<100, 64, 0, s0>>>(); // 在设备 0 上以 s0 启动核函数 —— 成功
cudaSetDevice(1);               // 设置设备 1 为当前设备
cudaStream_t s1;
cudaStreamCreate(&s1);          // 在设备 1 上创建流 s1
MyKernel<<<100, 64, 0, s1>>>(); // 在设备 1 上以 s1 启动核函数 —— 成功

// 以下核函数启动将失败：
MyKernel<<<100, 64, 0, s0>>>(); // 尝试在设备 1 上以 s0 启动 —— 失败！
```

- <strong>内存拷贝</strong>即使发到不与当前设备关联的流中，也会成功。也就是说，拷贝操作对流的设备亲和性约束不如核函数启动那么严格。

- <strong>`cudaEventRecord()`</strong> 如果输入事件和输入流关联到不同设备，将会失败。

- <strong>`cudaEventElapsedTime()`</strong> 如果两个输入事件关联到不同设备，将会失败。

- <strong>`cudaEventSynchronize()`</strong> 和 <strong>`cudaEventQuery()`</strong> 即使输入事件关联到不同于当前设备的设备，也会成功。

- <strong>`cudaStreamWaitEvent()`</strong> 即使输入流和输入事件关联到不同设备，也会成功。因此，`cudaStreamWaitEvent()` 可以用于同步多个设备彼此。

- 每个设备都有自己的默认流，因此发往一个设备默认流的命令可能与发往任何其他设备默认流的命令乱序或并发执行。

## 8.5 对等（Peer-to-Peer）内存访问

### 8.5.1 什么是 P2P 内存访问

根据系统属性（特别是 PCIe 和/或 NVLink 拓扑），设备可能能够寻址彼此的内存——即在一个设备上执行的核函数可以解引用指向另一设备内存的指针。这种 P2P（对等）内存访问特性在两个设备之间得到支持的前提是 `cudaDeviceCanAccessPeer()` 对这些设备返回 true。

P2P 内存访问仅在 64 位应用程序中受支持，且必须在两个设备之间通过调用 `cudaDeviceEnablePeerAccess()` 来启用。在非 NVSwitch 启用的系统上，每个设备最多支持系统范围内八个对等连接。

### 8.5.2 启用和使用 P2P 内存访问

P2P 内存访问与统一虚拟地址空间（UVA）配合使用——同一个指针可以在两个设备上用于寻址内存。以下代码示例展示了 P2P 内存访问的完整流程：

```cuda
cudaSetDevice(0);                   // 设置设备 0 为当前设备
float* p0;
size_t size = 1024 * sizeof(float);
cudaMalloc(&p0, size);              // 在设备 0 上分配内存
MyKernel<<<1000, 128>>>(p0);        // 在设备 0 上启动核函数
cudaSetDevice(1);                   // 设置设备 1 为当前设备
cudaDeviceEnablePeerAccess(0, 0);   // 启用与设备 0 的对等访问
                                    // （注意：不要在 flags 参数中传递任何非零值）

// 在设备 1 上启动核函数
// 此核函数可以访问设备 0 内存中地址为 p0 的数据
MyKernel<<<1000, 128>>>(p0);
```

关键点：`cudaDeviceEnablePeerAccess` 的第一个参数是被访问的远程设备的 ID，第二个参数保留且必须为 0。

启用 P2P 访问后，运行在设备 1 上的核函数可以直接通过指针 `p0` 读取或写入设备 0 的内存。这极大地简化了多 GPU 编程，因为你不再需要显式地将数据在设备之间拷贝。

### 8.5.3 查询 P2P 能力

在实际使用前，应查询 P2P 访问是否被支持：

```cuda
int canAccessPeer;
cudaDeviceCanAccessPeer(&canAccessPeer, deviceA, deviceB);
if (canAccessPeer) {
    cudaSetDevice(deviceA);
    cudaDeviceEnablePeerAccess(deviceB, 0);
} else {
    printf("P2P access from device %d to device %d is not supported\n",
           deviceA, deviceB);
}
```

### 8.5.4 Linux 上的 IOMMU 注意事项

仅在 Linux 上，CUDA 和显示驱动不支持启用了 IOMMU 的裸金属 PCIe 对等内存拷贝。然而，CUDA 和显示驱动通过 VM 直通支持 IOMMU。因此，在 Linux 上的原生裸金属系统上运行时，用户应禁用 IOMMU。对于虚拟机，应启用 IOMMU 并使用 VFIO 驱动作为 PCIe 直通。在 Windows 上，不存在上述限制。

## 8.6 对等（Peer-to-Peer）内存拷贝

### 8.6.1 P2P 内存拷贝函数

内存拷贝可以在两个不同设备的内存之间进行。当两个设备使用统一地址空间时（参见 8.7 节），使用常规内存拷贝函数即可完成 P2P 拷贝。

否则，需要使用专用的 P2P 拷贝函数：`cudaMemcpyPeer()`、`cudaMemcpyPeerAsync()`、`cudaMemcpy3DPeer()` 或 `cudaMemcpy3DPeerAsync()`。

以下代码示例展示了完整的 P2P 内存拷贝流程：

```cuda
cudaSetDevice(0);                   // 设置设备 0 为当前设备
float* p0;
size_t size = 1024 * sizeof(float);
cudaMalloc(&p0, size);              // 在设备 0 上分配内存
cudaSetDevice(1);                   // 设置设备 1 为当前设备
float* p1;
cudaMalloc(&p1, size);              // 在设备 1 上分配内存
cudaSetDevice(0);                   // 设置设备 0 为当前设备
MyKernel<<<1000, 128>>>(p0);        // 在设备 0 上启动核函数
cudaSetDevice(1);                   // 设置设备 1 为当前设备
cudaMemcpyPeer(p1, 1, p0, 0, size); // 将 p0 (设备0) 拷贝到 p1 (设备1)
MyKernel<<<1000, 128>>>(p1);        // 在设备 1 上启动核函数
```

`cudaMemcpyPeer` 的参数含义如下：
- `dst`：目标指针（在目标设备上）
- `dstDevice`：目标设备 ID
- `src`：源指针（在源设备上）
- `srcDevice`：源设备 ID
- `count`：拷贝的字节数

### 8.6.2 隐式 NULL 流中的 P2P 拷贝行为

在隐式 NULL 流中进行的两个不同设备内存之间的拷贝：
- 直到先前发往任一设备的所有命令都完成后才开始；
- 在执行完成之前，拷贝之后发往任一设备的任何命令都不能开始。

这与流的常规行为一致——异步拷贝可能与其他流中的拷贝或核函数重叠。

更重要的是，如果通过 `cudaDeviceEnablePeerAccess()` 启用了两设备间的 P2P 访问，则 P2P 内存拷贝不再需要通过主机中转，因此速度更快。这意味着启用 P2P 访问不仅允许直接内存访问，还能加速显式的 P2P 拷贝。

## 8.7 统一虚拟地址空间（UVA）

### 8.7.1 什么是 UVA

当应用程序作为 64 位进程运行时，主机和所有计算能力 2.0 及以上的设备使用<strong>单一地址空间（unified address space）</strong>。通过 CUDA API 调用进行的所有主机内存分配和受支持设备上的所有设备内存分配，都在此虚拟地址范围内。其结果是：

1. <strong>指针定位</strong>：通过 CUDA 分配的主机内存或使用统一地址空间的任何设备上的任何内存的位置，可以通过指针的值使用 `cudaPointerGetAttributes()` 来确定。

2. <strong>简化拷贝</strong>：在向或从使用统一地址空间的任何设备内存进行拷贝时，`cudaMemcpy*()` 的 `cudaMemcpyKind` 参数可以设置为 `cudaMemcpyDefault`，以便从指针确定位置。这对于非通过 CUDA 分配的主机指针也有效，只要当前设备使用统一寻址。

3. <strong>自动可移植内存</strong>：通过 `cudaHostAlloc()` 进行的分配在使用统一地址空间的所有设备上自动可移植（portable），并且由 `cudaHostAlloc()` 返回的指针可以直接从运行在这些设备上的核函数中使用——不再需要通过 `cudaHostGetDevicePointer()` 获取设备指针。

### 8.7.2 查询 UVA 支持

应用程序可以通过检查 `unifiedAddressing` 设备属性是否等于 1 来查询统一地址空间是否用于特定设备。

```cuda
cudaDeviceProp prop;
cudaGetDeviceProperties(&prop, deviceId);
if (prop.unifiedAddressing) {
    printf("Device %d supports Unified Virtual Addressing\n", deviceId);
}
```

### 8.7.3 UVA 的实际意义

UVA 极大地简化了 CUDA 编程。在没有 UVA 的时代，程序员需要手动跟踪每个指针是属于主机还是设备，并使用不同的拷贝参数。有了 UVA 之后：

- 可以直接使用 `cudaMemcpyDefault` 替代 `cudaMemcpyHostToDevice` / `cudaMemcpyDeviceToHost`，运行时库会根据指针值自动判断数据传输方向。
- 映射的页锁定内存（mapped memory）不再需要通过 `cudaHostGetDevicePointer()` 获取设备指针——`cudaHostAlloc()` 返回的指针可以直接在核函数中使用。
- 在 P2P 启用的多设备系统中，同一个设备指针可以在不同的 GPU 上直接使用，无需额外的地址转换。

## 8.8 进程间通信（IPC）

### 8.8.1 IPC 概述

由主机线程创建的任何设备内存指针或事件句柄，可以由同一进程内的任何其他线程直接引用。然而，它在进程外是无效的，因此不能被属于不同进程的线程直接引用。

为了跨进程共享设备内存指针和事件，应用程序必须使用<strong>进程间通信（Inter Process Communication, IPC）API</strong>。IPC API 仅在 Linux 上的 64 位进程中受支持，且设备计算能力需为 2.0 及以上。注意 IPC API 不支持 `cudaMallocManaged` 分配。

### 8.8.2 IPC 内存共享流程

使用 IPC API，应用程序可以：

1. 使用 `cudaIpcGetMemHandle()` 获取给定设备内存指针的 IPC 句柄；
2. 使用标准 IPC 机制（例如进程间共享内存或文件）将其传递给另一个进程；
3. 使用 `cudaIpcOpenMemHandle()` 从 IPC 句柄中检索设备指针，该指针在另一进程中是有效的。

事件句柄也可以使用类似的入口点共享。

### 8.8.3 IPC 的注意事项

- `cudaMalloc()` 进行的分配可能会从更大的内存块中为了性能原因进行子分配（sub-allocation）。在这种情况下，CUDA IPC API 将共享整个底层内存块，这可能导致其他子分配也被共享，进而可能导致进程之间的信息泄露。为防止此行为，建议仅共享具有 2MiB 对齐大小的分配。

- IPC 的一个典型使用场景是：单个主进程生成一批输入数据，使数据可供多个次要进程使用，而无需重新生成或拷贝。

- 使用 CUDA IPC 彼此通信的应用程序应使用相同的 CUDA 驱动和运行时进行编译、链接和运行。

- 从 CUDA 11.5 开始，仅事件共享 IPC API 在计算能力 7.x 及以上的 L4T 和嵌入式 Linux Tegra 设备上受支持。内存共享 IPC API 在 Tegra 平台上仍不受支持。

### 8.8.4 IPC 示例流程（概念性）

以下是一个简化的 IPC 使用流程概念：

<strong>进程 A（导出端）：</strong>

```cuda
// 分配设备内存
float* d_data;
cudaMalloc(&d_data, dataSize);

// 计算数据...
MyKernel<<<grid, block>>>(d_data);
cudaDeviceSynchronize();

// 获取 IPC 句柄
cudaIpcMemHandle_t memHandle;
cudaIpcGetMemHandle(&memHandle, d_data);

// 通过某种 IPC 机制（文件、共享内存、socket 等）将 memHandle 发送给进程 B
sendToProcessB(&memHandle, sizeof(cudaIpcMemHandle_t));
```

<strong>进程 B（导入端）：</strong>

```cuda
// 从进程 A 接收 IPC 句柄
cudaIpcMemHandle_t memHandle;
receiveFromProcessA(&memHandle, sizeof(cudaIpcMemHandle_t));

// 打开 IPC 句柄获取本地指针
float* d_remoteData;
cudaIpcOpenMemHandle((void**)&d_remoteData, memHandle,
                     cudaIpcMemLazyEnablePeerAccess);

// 现在可以像本地内存一样使用 d_remoteData
MyKernel<<<grid, block>>>(d_remoteData);

// 使用完毕后关闭
cudaIpcCloseMemHandle(d_remoteData);
```

## 8.9 错误检查

### 8.9.1 CUDA 错误模型

所有运行时函数都返回错误码。但对于异步函数，这个错误码无法报告可能在设备上发生的任何异步错误，因为该函数在设备完成任务之前就返回了；错误码仅报告在主机上执行任务之前发生的错误，通常与参数验证相关。如果发生异步错误，它将由后续某个不相关的运行时函数调用报告。

### 8.9.2 检查异步错误的正确方法

在某个异步函数调用之后检查异步错误的唯一方法是，在调用之后立即进行同步——通过调用 `cudaDeviceSynchronize()`（或使用其他同步机制），然后检查 `cudaDeviceSynchronize()` 返回的错误码。

### 8.9.3 cudaGetLastError 与 cudaPeekAtLastError

运行时为每个主机线程维护一个错误变量，该变量初始化为 `cudaSuccess`，并在每次发生错误时被错误码覆盖（无论是参数验证错误还是异步错误）。

- <strong>`cudaPeekAtLastError()`</strong>：返回此错误变量但不重置它。
- <strong>`cudaGetLastError()`</strong>：返回此错误变量并将其重置为 `cudaSuccess`。

核函数启动不返回任何错误码，因此必须在核函数启动之后立即调用 `cudaPeekAtLastError()` 或 `cudaGetLastError()` 来检索任何启动前错误。为确保 `cudaPeekAtLastError()` 或 `cudaGetLastError()` 返回的任何错误不源自核函数启动之前的调用，必须确保运行时错误变量在核函数启动之前被设置为 `cudaSuccess`——例如，在核函数启动之前调用 `cudaGetLastError()`。核函数启动是异步的，因此要检查异步错误，应用程序必须在核函数启动和 `cudaPeekAtLastError()` 或 `cudaGetLastError()` 调用之间进行同步。

### 8.9.4 推荐的错误检查宏

在实际项目中，推荐使用宏来简化错误检查。以下是一个常用的错误检查宏：

```cuda
#include <stdio.h>

#define CUDA_CHECK(err) \
    do { \
        cudaError_t err_r = (err); \
        if (err_r != cudaSuccess) { \
            fprintf(stderr, "CUDA Error at %s:%d - %s\n", \
                    __FILE__, __LINE__, cudaGetErrorString(err_r)); \
            exit(EXIT_FAILURE); \
        } \
    } while(0)

// 使用示例
CUDA_CHECK(cudaMalloc(&d_ptr, size));
CUDA_CHECK(cudaMemcpy(d_ptr, h_ptr, size, cudaMemcpyHostToDevice));
MyKernel<<<grid, block>>>(d_ptr);
CUDA_CHECK(cudaGetLastError());           // 检查核函数启动错误
CUDA_CHECK(cudaDeviceSynchronize());      // 同步并检查异步错误
```

一些关键实践：
- 每次 CUDA API 调用后检查返回值。
- 核函数启动后立即检查 `cudaGetLastError()` 以捕获启动参数错误。
- 在合适的同步点（或程序结束前）调用 `cudaDeviceSynchronize()` 来捕获异步错误。

### 8.9.5 cudaErrorNotReady 的特殊性

注意，`cudaStreamQuery()` 和 `cudaEventQuery()` 可能返回的 `cudaErrorNotReady` 不被视为错误，因此不会被 `cudaPeekAtLastError()` 或 `cudaGetLastError()` 报告。这是合理的——查询一个流或事件是否就绪，返回"未就绪"是一种正常的、预期的状态。

## 8.10 动手体验：多设备 P2P 性能测试

下面我们编写一个完整的程序，演示多设备枚举、P2P 访问启用、以及 P2P 拷贝与单纯主机中转拷贝的性能对比。

### 8.10.1 完整代码

```cuda
#include <stdio.h>
#include <cuda_runtime.h>

#define CUDA_CHECK(call) \
    do { \
        cudaError_t err = call; \
        if (err != cudaSuccess) { \
            fprintf(stderr, "CUDA Error at %s:%d - %s\n", \
                    __FILE__, __LINE__, cudaGetErrorString(err)); \
            return -1; \
        } \
    } while(0)

int main() {
    int deviceCount;
    CUDA_CHECK(cudaGetDeviceCount(&deviceCount));

    if (deviceCount < 2) {
        printf("This test requires at least 2 CUDA devices. Found %d.\n", deviceCount);
        return 0;
    }

    printf("Found %d CUDA device(s)\n\n", deviceCount);

    // 打印设备信息
    for (int i = 0; i < deviceCount; i++) {
        cudaDeviceProp prop;
        CUDA_CHECK(cudaGetDeviceProperties(&prop, i));
        printf("Device %d: %s (Compute %d.%d, %.2f GB)\n",
               i, prop.name, prop.major, prop.minor,
               prop.totalGlobalMem / (1024.0 * 1024.0 * 1024.0));
    }

    // 检查设备 0 和 1 之间的 P2P 能力
    int canAccess01, canAccess10;
    CUDA_CHECK(cudaDeviceCanAccessPeer(&canAccess01, 0, 1));
    CUDA_CHECK(cudaDeviceCanAccessPeer(&canAccess10, 1, 0));

    printf("\nP2P Access: Device 0 -> Device 1: %s\n",
           canAccess01 ? "Supported" : "Not Supported");
    printf("P2P Access: Device 1 -> Device 0: %s\n",
           canAccess10 ? "Supported" : "Not Supported");

    // 测试数据大小：16MB
    const size_t dataSize = 16 * 1024 * 1024;  // 16 MB
    const size_t numFloats = dataSize / sizeof(float);
    float *d_data0, *d_data1;
    float *h_data;

    // 分配设备内存
    CUDA_CHECK(cudaSetDevice(0));
    CUDA_CHECK(cudaMalloc(&d_data0, dataSize));
    CUDA_CHECK(cudaSetDevice(1));
    CUDA_CHECK(cudaMalloc(&d_data1, dataSize));

    // 分配页锁定主机内存
    CUDA_CHECK(cudaMallocHost(&h_data, dataSize));

    // 初始化数据
    for (size_t i = 0; i < numFloats; i++) {
        h_data[i] = (float)i;
    }

    // 将数据拷贝到设备 0
    CUDA_CHECK(cudaSetDevice(0));
    CUDA_CHECK(cudaMemcpy(d_data0, h_data, dataSize, cudaMemcpyHostToDevice));

    // 创建事件用于计时
    cudaEvent_t start, stop;
    CUDA_CHECK(cudaEventCreate(&start));
    CUDA_CHECK(cudaEventCreate(&stop));
    float elapsedTime;

    // === 测试1: P2P 直接拷贝（使用 cudaMemcpyPeer）===
    CUDA_CHECK(cudaSetDevice(0));
    CUDA_CHECK(cudaEventRecord(start, 0));
    CUDA_CHECK(cudaMemcpyPeer(d_data1, 1, d_data0, 0, dataSize));
    CUDA_CHECK(cudaEventRecord(stop, 0));
    CUDA_CHECK(cudaEventSynchronize(stop));
    CUDA_CHECK(cudaEventElapsedTime(&elapsedTime, start, stop));
    printf("\n=== P2P Memory Copy Performance ===\n");
    printf("P2P direct copy (cudaMemcpyPeer): %.3f ms, Bandwidth: %.2f GB/s\n",
           elapsedTime, (dataSize / (elapsedTime / 1000.0)) / (1024.0 * 1024.0 * 1024.0));

    // === 测试2: 通过主机中转的拷贝 ===
    CUDA_CHECK(cudaSetDevice(0));
    CUDA_CHECK(cudaEventRecord(start, 0));
    // 设备 0 -> 主机
    CUDA_CHECK(cudaMemcpy(h_data, d_data0, dataSize, cudaMemcpyDeviceToHost));
    // 主机 -> 设备 1
    CUDA_CHECK(cudaSetDevice(1));
    CUDA_CHECK(cudaMemcpy(d_data1, h_data, dataSize, cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaEventRecord(stop, 0));
    CUDA_CHECK(cudaEventSynchronize(stop));
    CUDA_CHECK(cudaEventElapsedTime(&elapsedTime, start, stop));
    printf("Host-staged copy (D2H + H2D):   %.3f ms, Bandwidth: %.2f GB/s\n",
           elapsedTime, (dataSize / (elapsedTime / 1000.0)) / (1024.0 * 1024.0 * 1024.0));

    // === 测试3: 尝试启用 P2P 访问后的 UVA 直接访问 ===
    if (canAccess01 && canAccess10) {
        CUDA_CHECK(cudaSetDevice(0));
        CUDA_CHECK(cudaDeviceEnablePeerAccess(1, 0));
        CUDA_CHECK(cudaSetDevice(1));
        CUDA_CHECK(cudaDeviceEnablePeerAccess(0, 0));

        // 使用 cudaMemcpyDefault 进行 P2P 拷贝
        CUDA_CHECK(cudaSetDevice(0));
        CUDA_CHECK(cudaEventRecord(start, 0));
        CUDA_CHECK(cudaMemcpy(d_data1, d_data0, dataSize, cudaMemcpyDefault));
        CUDA_CHECK(cudaEventRecord(stop, 0));
        CUDA_CHECK(cudaEventSynchronize(stop));
        CUDA_CHECK(cudaEventElapsedTime(&elapsedTime, start, stop));
        printf("P2P copy via cudaMemcpyDefault:   %.3f ms, Bandwidth: %.2f GB/s\n",
               elapsedTime,
               (dataSize / (elapsedTime / 1000.0)) / (1024.0 * 1024.0 * 1024.0));

        printf("\nP2P access enabled successfully. Same pointer can be used on both devices.\n");
    }

    // 清理资源
    CUDA_CHECK(cudaFreeHost(h_data));
    CUDA_CHECK(cudaSetDevice(0));
    CUDA_CHECK(cudaFree(d_data0));
    CUDA_CHECK(cudaSetDevice(1));
    CUDA_CHECK(cudaFree(d_data1));
    CUDA_CHECK(cudaEventDestroy(start));
    CUDA_CHECK(cudaEventDestroy(stop));

    printf("\nTest completed successfully.\n");
    return 0;
}
```


## 8.11 错误检查模式与最佳实践

### 8.11.1 通用错误检查宏

在实际 CUDA 项目中，逐个调用检查错误码会使代码冗长而难以维护。以下是几种推荐的错误检查宏模式：

<strong>（1）基础版本：</strong>

```cuda
#define CUDA_CHECK(call) \
    do { \
        cudaError_t err = call; \
        if (err != cudaSuccess) { \
            fprintf(stderr, "CUDA Error at %s:%d - %s\n", \
                    __FILE__, __LINE__, cudaGetErrorString(err)); \
            exit(EXIT_FAILURE); \
        } \
    } while(0)
```

<strong>（2）带有自定义错误消息的版本：</strong>

```cuda
#define CUDA_CHECK_MSG(call, msg) \
    do { \
        cudaError_t err = call; \
        if (err != cudaSuccess) { \
            fprintf(stderr, "CUDA Error [%s] at %s:%d - %s\n", \
                    msg, __FILE__, __LINE__, cudaGetErrorString(err)); \
            exit(EXIT_FAILURE); \
        } \
    } while(0)
```

<strong>（3）核函数专用的检查宏：</strong>

```cuda
#define CUDA_CHECK_KERNEL() \
    do { \
        cudaError_t err = cudaGetLastError(); \
        if (err != cudaSuccess) { \
            fprintf(stderr, "Kernel launch error at %s:%d - %s\n", \
                    __FILE__, __LINE__, cudaGetErrorString(err)); \
            exit(EXIT_FAILURE); \
        } \
    } while(0)
```

使用模式：

```cuda
// API 调用检查
CUDA_CHECK(cudaMalloc(&d_ptr, size));
CUDA_CHECK(cudaMemcpy(d_ptr, h_ptr, size, cudaMemcpyHostToDevice));

// 核函数启动后检查
myKernel<<<grid, block, sharedMem, stream>>>(d_ptr, N);
CUDA_CHECK_KERNEL();

// 显式同步以捕获异步错误
CUDA_CHECK(cudaDeviceSynchronize());
```

### 8.11.2 异常安全的 CUDA 资源管理（RAII）

在 C++ 项目中，推荐使用 RAII（Resource Acquisition Is Initialization）模式管理 CUDA 资源，以避免内存泄漏和资源泄漏。以下是一些示例：

```cpp
// CUDA 设备内存的 RAII 包装
class CudaMemory {
    void* ptr_;
    size_t size_;
    int device_;
public:
    CudaMemory(size_t size) : size_(size) {
        cudaGetDevice(&device_);
        cudaMalloc(&ptr_, size_);
    }
    ~CudaMemory() {
        cudaSetDevice(device_);
        cudaFree(ptr_);
    }
    void* get() const { return ptr_; }
    size_t size() const { return size_; }
    // 禁止拷贝，允许移动
    CudaMemory(const CudaMemory&) = delete;
    CudaMemory& operator=(const CudaMemory&) = delete;
    CudaMemory(CudaMemory&& other) noexcept
        : ptr_(other.ptr_), size_(other.size_), device_(other.device_) {
        other.ptr_ = nullptr;
    }
};

// CUDA 流的 RAII 包装
class CudaStream {
    cudaStream_t stream_;
public:
    CudaStream(unsigned flags = cudaStreamDefault) {
        cudaStreamCreateWithFlags(&stream_, flags);
    }
    ~CudaStream() { cudaStreamDestroy(stream_); }
    cudaStream_t get() const { return stream_; }
    void synchronize() { cudaStreamSynchronize(stream_); }
};
```

### 8.11.3 多 GPU 编程模式

<strong>模式 1：数据并行——每个 GPU 处理一部分数据</strong>

这是最直接的多 GPU 编程模式。将数据均匀分配到各 GPU，每块 GPU 独立处理自己的数据部分。

```cuda
// 主线程管理所有 GPU
int numGPUs;
cudaGetDeviceCount(&numGPUs);

for (int gpu = 0; gpu < numGPUs; gpu++) {
    cudaSetDevice(gpu);
    // 为每个 GPU 分配独立的内存
    // 拷贝对应数据块
    // 启动核函数
}

// 等待所有 GPU 完成
for (int gpu = 0; gpu < numGPUs; gpu++) {
    cudaSetDevice(gpu);
    cudaDeviceSynchronize();
}
```

<strong>模式 2：流水线并行——GPU 之间传递中间结果</strong>

当算法可以分解为多个阶段时，可以让不同的 GPU 负责不同的阶段，通过 P2P 传输中间结果。

```cuda
// GPU 0 处理阶段 1
cudaSetDevice(0);
stage1_kernel<<<grid, block>>>(input, intermediate);

// P2P 传输到 GPU 1
cudaMemcpyPeer(d_intermediate_1, 1, d_intermediate_0, 0, size);

// GPU 1 处理阶段 2
cudaSetDevice(1);
cudaStreamWaitEvent(stream, done_copy_event, 0);  // 等待数据就绪
stage2_kernel<<<grid, block, 0, stream>>>(intermediate, output);
```

<strong>模式 3：模型并行——每个 GPU 持有模型的一部分</strong>

这种模式在深度学习训练中很常见。每个 GPU 持有一部分模型参数，计算需要跨 GPU 的通信（通常使用 NCCL 等集合通信库）。

<strong>模式 4：多线程驱动多 GPU</strong>

对于需要同时驱动多块 GPU 的场景，可以用多个 CPU 线程分别管理不同的 GPU：

```cuda
#include <thread>
#include <vector>

void gpuWorker(int deviceId, float* data, size_t size) {
    cudaSetDevice(deviceId);
    // 每个线程独立管理一个 GPU
    float* d_data;
    cudaMalloc(&d_data, size);
    cudaStream_t stream;
    cudaStreamCreate(&stream);
    // ... 执行 GPU 操作
    cudaStreamSynchronize(stream);
    cudaFree(d_data);
    cudaStreamDestroy(stream);
}

int main() {
    int numGPUs;
    cudaGetDeviceCount(&numGPUs);
    std::vector<std::thread> threads;
    for (int i = 0; i < numGPUs; i++) {
        threads.emplace_back(gpuWorker, i, ...);
    }
    for (auto& t : threads) {
        t.join();
    }
    return 0;
}
```

### 8.11.4 NVLink 与 PCIe 拓扑

多 GPU 系统中，GPU 之间的互联拓扑对 P2P 性能影响巨大。主要的互联技术包括：

- <strong>PCIe 交换机（PCIe Switch）</strong>：最基础的互联方式。经由 PCIe 交换机连接的 GPU 之间的 P2P 通信需要通过 PCIe 交换机转发，带宽受限于 PCIe 总线的带宽。例如，PCIe 3.0 x16 提供约 16 GB/s 的单向带宽。

- <strong>NVLink</strong>：NVIDIA 专有的高带宽互联技术。NVLink 提供远超 PCIe 的带宽——例如，NVLink 2.0 每条链路提供 25 GB/s 双向带宽，V100 通过 6 条链路可达到 300 GB/s 的总带宽。

- <strong>NVSwitch</strong>：在 DGX 等高端系统中，NVSwitch 芯片连接所有 GPU 形成全互联拓扑，消除拓扑瓶颈。

应用程序可以通过 `cudaDeviceGetP2PAttribute()` 查询 P2P 连接的详细属性（包括带宽），但此类查询需要较新的 CUDA 版本。

查询代码示例：

```cuda
int perfRank;
cudaDeviceGetP2PAttribute(&perfRank, cudaDevP2PAttrPerformanceRank, 0, 1);
printf("P2P Performance Rank from device 0 to device 1: %d\n", perfRank);
// 返回 0 表示最优性能（直连），数值越大性能越差
```

## 8.12 本章小结

本章全面介绍了 CUDA 多设备系统的编程模型，主要内容包括：

1. <strong>设备枚举</strong>使用 `cudaGetDeviceCount()` 和 `cudaGetDeviceProperties()` 来发现和查询系统中的所有 GPU。

2. <strong>设备选择</strong>通过 `cudaSetDevice()` 切换当前活动设备，每个主机线程独立维护其当前设备。在未显式设置时默认使用设备 0。

3. <strong>流和事件</strong>在多设备环境中与创建它们的设备绑定。核函数启动必须在与流匹配的设备上执行，而 `cudaStreamWaitEvent()` 是实现跨设备同步的重要工具。

4. <strong>P2P 内存访问</strong>允许一个 GPU 直接访问另一个 GPU 的内存，通过 `cudaDeviceEnablePeerAccess()` 启用。这对多 GPU 编程至关重要。

5. <strong>P2P 内存拷贝</strong>使用 `cudaMemcpyPeer()` 等函数在设备之间直接传输数据，避免通过主机中转，显著提升带宽。

6. <strong>统一虚拟地址空间（UVA）</strong>在 64 位应用中，主机和所有设备的指针位于单一地址空间内，简化了数据传输和内存管理。

7. <strong>进程间通信（IPC）</strong>通过 `cudaIpcGetMemHandle()` / `cudaIpcOpenMemHandle()` 实现跨进程的设备内存共享。

8. <strong>错误检查</strong>需要特别注意 CUDA 的异步错误模型。使用 `cudaGetLastError()` 和 `cudaDeviceSynchronize()` 的组合是捕获异步错误的标准方法。建议使用宏来统一错误检查代码。
